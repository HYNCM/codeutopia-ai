# CodeUtopia AI 协作框架 v2.0

> **核心认知**：AI Agent 不是"虚拟员工"，而是**增强人类能力的工具**。本文档定义的是**人机协作模式**，而非"AI 团队管理"。

---

## 🧠 第一性原理：理解 AI Agent 的本质

### 什么是 AI Agent？
```
AI Agent = LLM + Memory + Tools + Loop
```
- **LLM**：语言模型，擅长理解和生成文本
- **Memory**：上下文窗口（短期）+ 外部存储（长期）
- **Tools**：代码执行、文件操作、API调用等能力
- **Loop**：观察 → 思考 → 行动 → 反馈 的循环

### 关键限制（必须牢记）
| 限制 | 影响 | 应对策略 |
|------|------|----------|
| 上下文窗口有限 | 无法一次性处理整个代码库 | 分块处理 + 知识索引 |
| 无持久记忆 | 每次对话都是"新生" | 显式维护 CONTEXT.md |
| 幻觉 (Hallucination) | 可能编造不存在的 API | 要求引用来源 + 验证执行 |
| 无法真正"并行" | 多角色只是串行切换 | 减少角色切换，聚焦单任务 |

## 👤 人机边界：谁做决策，谁执行

### 人类的职责 (YOU)
- ✅ 定义目标和优先级
- ✅ 审核关键决策（技术选型、架构）
- ✅ 验收最终产出
- ✅ 提供业务上下文和约束条件
- ✅ 打断错误方向

### AI 的职责 (AGENT)
- ✅ 执行明确定义的任务
- ✅ 生成代码、文档、测试
- ✅ 分析和建议（但人类决定是否采纳）
- ✅ 检索和整理信息
- ❌ **不应该**：自主做出不可逆的决策

## 🎭 Persona 模式：一个模型，多种视角

> "角色"不是独立的 Agent，而是**同一 AI 的不同思考模式**。

### 核心 Personas（按需激活）

| Persona | 激活场景 | System Prompt 关键词 | 输出物 |
|---------|---------|---------------------|--------|
| **Analyst** | 需求不明确时 | "作为产品分析师，拆解需求..." | 结构化 PRD |
| **Architect** | 技术决策时 | "作为系统架构师，评估方案..." | 技术规格 + ADR |
| **Coder** | 实现功能时 | "作为资深开发者，编写代码..." | 可运行代码 |
| **Reviewer** | 代码完成后 | "作为代码审查员，检查..." | Review 意见 |
| **Tester** | 需要验证时 | "作为 QA 工程师，设计测试..." | 测试用例 |

## 📂 知识管理：让 AI "记住"项目

### 问题
AI 每次对话都是"失忆"的，如何让它理解项目？

### 解决方案：三层记忆架构

```
+---------------------------------------------+
|  Layer 1: System Context (系统上下文)        |
|  - 项目简介、技术栈、代码规范                |
|  - 位置: /CLAUDE.md 或 /.cursorrules         |
+---------------------------------------------+
|  Layer 2: Session Context (会话上下文)       |
|  - 当前任务目标、已完成步骤                  |
|  - 位置: 对话历史 + /docs/CURRENT_TASK.md    |
+---------------------------------------------+
|  Layer 3: Retrieval Context (检索上下文)     |
|  - 相关代码片段、历史决策                    |
|  - 来源: 语义搜索 + 文件引用                 |
+---------------------------------------------+
```

### 必须维护的文件

| 文件 | 内容 | 更新频率 |
|------|------|----------|
| CLAUDE.md | 项目规则、禁止事项、偏好 | 项目初始化时 |
| docs/ARCHITECTURE.md | 系统架构、模块边界 | 架构变更时 |
| docs/DECISIONS.md | 重要技术决策及原因 (ADR) | 每次重大决策后 |
| docs/CURRENT_TASK.md | 当前进行中的任务状态 | 每次会话开始/结束 |

## 🔄 工作流：增量迭代，而非瀑布

### 真实的开发循环

```
     +--------------------------------------+
     |                                      |
     v                                      |
+---------+    +---------+    +---------+   |
| Clarify |--->|  Plan   |--->| Execute |---+
|  澄清   |    |  规划   |    |  执行   |   |
+---------+    +---------+    +---------+   |
     ^                              |       |
     |         +---------+          |       |
     +---------| Review  |<---------+       |
               |  检视   |                  |
               +----+----+                  |
                    | OK                    |
                    v                       |
               +---------+                  |
               |  Ship   |------------------+
               |  交付   |   (下一个任务)
               +---------+
```

### 每个阶段的 AI 使用方式

| 阶段 | 人类做什么 | AI 做什么 |
|------|-----------|----------|
| **Clarify** | 描述目标 | 提问澄清、拆解需求 |
| **Plan** | 审核方案 | 生成技术方案、估算工作量 |
| **Execute** | 监督进度 | 编写代码、创建文件 |
| **Review** | 最终确认 | 自查代码、运行测试 |
| **Ship** | 合并/部署 | 更新文档、清理临时文件 |

## ⚠️ 风险控制：防止 AI 失控

### 1. 强制检查点 (Checkpoints)
在以下情况，AI 必须暂停并请求人类确认：
- [ ] 删除任何文件
- [ ] 修改超过 100 行的单个文件
- [ ] 安装新的依赖包
- [ ] 修改数据库 Schema
- [ ] 任何涉及认证/支付的代码

### 2. 输出验证
所有 AI 生成的代码必须：
- [ ] 通过 TypeScript 编译
- [ ] 通过 ESLint 检查
- [ ] 有对应的测试用例（关键路径）
- [ ] 不包含 any 类型（除非显式注释原因）

### 3. 幻觉防护
当 AI 引用 API 或库时：
- 要求提供官方文档链接
- 优先使用项目中已存在的模式
- 对不确定的内容标注 // TODO: verify

## 🎯 最佳实践

### Do ✅
- 每次只给 AI 一个明确的任务
- 提供足够的上下文（相关文件、约束）
- 让 AI 先说计划，再执行
- 小步快跑，频繁验证

### Don't ❌
- 不要让 AI 自己决定"做什么"
- 不要一次性要求完成整个功能
- 不要跳过 Review 直接合并
- 不要假设 AI 记得上次对话的内容

## 📊 效能指标

### 衡量 AI 协作质量的指标

| 指标 | 定义 | 目标 |
|------|------|------|
| **首次正确率** | AI 生成的代码无需修改直接可用的比例 | > 60% |
| **迭代次数** | 完成一个任务需要的人机交互轮数 | < 5 轮 |
| **幻觉率** | AI 生成的代码中包含不存在 API 的比例 | < 5% |
| **上下文召回** | AI 正确引用项目已有代码的比例 | > 80% |

## 🔮 持续进化

### 每周回顾
1. 哪些任务 AI 做得好？为什么？
2. 哪些任务 AI 做得差？缺少什么上下文？
3. 需要更新 CLAUDE.md 吗？
4. 有新的模式可以固化吗？

### 知识沉淀
- 成功的 Prompt 模板 -> 保存到 /prompts/
- 反复出现的问题 -> 更新到 CLAUDE.md 的禁止列表
- 好的代码模式 -> 作为示例加入上下文

---

> **记住**：AI 是放大器，不是替代者。好的工程师 + AI = 10x 效率。差的工程师 + AI = 10x 混乱。
